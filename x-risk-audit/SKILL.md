# x-risk-audit — X 账号风控检测

对 X 账号做一轮完整风控：**关注流 + 本人发帖 + 本人回复**三面扫描，输出分级处置报告。全流程只读。

> 另有 Chrome 扩展（仓库 `extension/`）做**实时**标记：刷到命中规则的推文当场描边+徽标，与 skill 的周期性深度检测互补，两者共用同一份规则 JSON。用法见 `extension/README` 一节。

## Important（必须先读的纪律）

1. **只读**。整个流程禁止任何写操作：不发帖、不点赞、不转发、不关注/取关、不发私信。处置建议只写进报告，由用户自己执行。
2. **登录靠用户**。账号凭证属于 Tier 1 用户操作：检测通道未登录时，把窗口交给用户登录（或让用户指定一个已登录的浏览器通道），绝不代填密码/验证码，绝不切换通道绕过登录墙。
3. **数据不出本机**。抓取到的帖子是用户隐私数据：只落盘到本地工作目录，写进 git 忽略清单，**绝不提交、绝不上传、绝不贴进报告以外的对话**。报告正文引用他人帖子时保留必要原文（属正当使用），但不要在仓库、issue、评论里扩散。
4. **抓取要有节制**。X 对高频滚动会返回 429。每轮滚动间隔 ≥1.2 秒，总轮次按用户选的时间范围收敛，不要无脑拉几百屏。

## 工作流（按顺序执行）

### Step 0 — 与用户确认两个参数（弹窗）

用弹窗一次问清，不要纯文本提问：

- **检测口径**：全部类别 / 仅个人隐私 / 仅凭据密钥 / 仅敏感违规话题（默认全部）
- **时间范围**：最近 24 小时 / 7 天 / 30 天 / 尽可能多（多屏滚动）。范围决定滚动量，也决定耗时与 429 风险。

### Step 1 — 选择抓取通道

优先顺序：

1. **Tabbit**（`$HOME/.local/bin/tabbit-cli`）——用户日常浏览器，大概率已登录 X。先 `create --task NAME` 看 inventory，找 url 含 `x.com` 的标签页 `--tab ID` 接管。
2. 若无 Tabbit 或无 X 标签：用共享 Node REPL 的 `agent.browsers`（IAB 内置浏览器）新开标签，跳到登录页后**把浏览器窗口显示出来**（visibility capability `set(true)`），请用户登录后告知；用户回答"已登录"后再自己验证（访问 `/home` 是否被重定向到登录页）。
3. 只有 X 标签页是接管对象。**不要动用户的其他标签页**（邮件、其他站点）。

通道不可用或登录失败：如实报告阻塞，不要换通道偷偷继续。

### Step 2 — 抓取三类数据

先读 `references/x-scraping-playbook.md`，里面有完整可抄的 JS、字段定义（u/t/d/l/s）与落盘格式。三个必须记住的点：

1. **`x.com/home` 默认是"为你推荐"流**，含非关注账号，不符合口径。必须先点「正在关注」标签（`getByRole("tab", { name: /关注/ })`）。
2. **X 虚拟滚动会删掉滑出屏幕的推文**：必须"滚动 → 等 1.3s 稳定 → 抽取 → 再等 0.9s 二次抽取"，且**单个 nodejs 程序内一次性完成抓取并 `fs.writeFileSync` 落盘**——不要把累积状态寄托在跨调用全局变量上（会静默丢数据，本次实测丢过 2 条）。
3. 三个目标页面：关注流（`/home` + 关注标签）、本人帖子（`/USERNAME`）、本人回复（`/USERNAME/with_replies`）。合并时按 status 链接去重；关注流非严格时间序，多轮抓取要合并。

### Step 3 — 运行扫描器

```bash
python3 scripts/risk_scan.py <合并后的.json> --own-handle <用户handle> [--out findings.tsv]
```

规则是**单一数据源** `rules/sensitive-rules.json`（Python 扫描器与未来的 Chrome 扩展共用）：改规则只改这个 JSON，不要动 risk_scan.py 里的正则。改动规则后必须跑回归：

```bash
python3 scripts/test_scan.py   # 33 条合成 fixtures 的冻结预期，PASS 才算改对
```

规则全集、误报处置与定级口径见 `references/detection-rules.md`；输出 TSV 列为分组、类别、作者、日期、命中词、帖子链接、正文摘要，汇总数走 stderr。

### Step 4 — 人工复核（不可跳过）

规则引擎误报率不低，逐条过一遍：

- "住在同一层楼""约炮了（骂人口癖）"这类叙事/粗口不是隐私泄露或招嫖；
- 19 位推特 snowflake ID 不是身份证（脚本已排除，仍要抽查）；
- 引用的推文（quote tweet）作者是原作者——别把别人主页的错当成用户的错；
- "关注博主"分组里的推文是他人内容，定级要写清"在你关注流中出现"，不是"你发了"。

复核后把有效发现分为四档：**高风险**（涉本人安全的执法传闻、暴力、歧视煽动）、**中风险**（色情低俗、争议言论、刷粉机器人）、**低风险**（误报排除项、玩笑语境）、**干净**。

### Step 5 — 写报告并交付

按 `references/report-template.md` 的骨架写，Markdown 落盘到工作目录并 present_files。骨架六节：检测概况（对象、时间、口径、样本量、方法）→ 结论速览表 → 关注博主敏感内容明细（作者、链接、摘要、风险说明、处置建议）→ 本人帖子检测结果（逐类说明未检出，附习惯提醒）→ 处置建议（立即做/近期保持/持续保持三档）→ 覆盖度与局限。

### Step 6 — 清理

- Tabbit 通道：`tabbit-cli finish --task NAME`（释放接管、保留用户标签页；若 finish 报告 `SITE_RATE_LIMITED` 429 警告，向用户说明"抓取偏频繁被限流，无害"）。
- IAB 通道：关掉本任务新建的标签页，保留用户原有标签页。

## Examples

- 用户："检查下我 X 上关注的博主有没有发敏感信息的，我发的帖子也看看" → 弹窗确认口径/范围 → Tabbit 接管已登录 X → 抓关注流+主页 → 扫描 → 复核 → 报告。
- 用户："帮我做一轮账号风控" → 同上；若 Tabbit 未登录，显示 IAB 登录页请用户登录，验证登录态后继续。
- 用户："看看我的推文有没有泄露手机号密码什么的" → 口径选仅 PII+凭据，仍建议全量扫（成本差别不大）。

## Troubleshooting

| 现象 | 原因 | 处置 |
|---|---|---|
| 抓取数轮后 total 不再增长但日期很新 | 虚拟滚动 + 停滞判定过早 | 每轮双次抽取 +  stagnant 阈值 ≥5，再跑一轮全量单程序抓取 |
| 后续调用发现早前抓的数据少了 | 跨调用全局变量丢状态 | 所有累积放在单次 nodejs 程序内，直接写文件 |
| `write` 工具写花体 Unicode 推文失败 | 数学字母数字符号破坏传输 | 用 Python heredoc 落盘，不要过手写内容 |
| finish 报告 429 | X 限流 | 降低滚动频率；告知用户无害 |
| 跳转登录页 | 通道未登录 | Tier 1：交还用户登录，不代填 |
| 关注流时间跳乱 | X 关注流非严格时间序 | 多轮抓取合并去重，报告注明覆盖窗口 |
| 被抓账号内容含引用的推文 | quote tweet 展示原作者 | User-Name 取到原作者时按引用内容归类，不算账号本人发布 |
