# 检测规则全集（detection-rules）

扫描器 `scripts/risk_scan.py` 内置四类规则。每条规则给出**查什么、为什么、已知误报**。新增规则时同步更新本文档和脚本。

## 1. 个人隐私（PII）

| 规则 | 模式 | 说明 |
|---|---|---|
| 中国手机号 | `(?<!\d)1[3-9]\d{9}(?!\d)` | 11 位；前后不能是数字，防止吃掉长数字串 |
| 身份证号 | `(?<!\d)\d{17}[\dXx](?!\d)` + 出生日期段合法性校验（1900–2030 年、月 1–12、日 1–31） | 18 位。**必须排除 19 位推特 snowflake ID**（以 2 开头的 19 位纯数字是推文 ID，不是身份证） |
| 银行卡号 | `(?<!\d)\d{16,19}(?!\d)` + Luhn 校验 | 纯正则会把推文 ID/订单号卷进来，Luhn 能挡掉绝大多数误报 |
| 电子邮箱 | 标准邮箱正则 | 公开邮箱多为用户主动公开，命中后由人工判断是否敏感 |
| 地址门牌 | `(路|街|巷|道|弄|号|栋|单元|室|层)\s*\d+` | "3 栋 2 单元"这类；命中率不低，几乎都要人工复核 |
| 住址关键词 | `(我家在|住在|地址是|收货地址|现居|家住)[^\n。]{0,30}` | 语境触发，比门牌号准 |

已知误报：叙事句里的"住在同一层楼"（不是真实住址）；"约炮了"作为粗口抱怨（不是招嫖）；推文 ID 被判身份证/银行卡（校验已挡，仍抽查）。

## 2. 凭据密钥

| 规则 | 模式 |
|---|---|
| OpenAI/通用 | `sk-[A-Za-z0-9_\-]{16,}` |
| Google API Key | `AIza[0-9A-Za-z_\-]{30,}` |
| GitHub Token | `(ghp\|gho\|ghu\|ghs\|ghr)_[A-Za-z0-9]{20,}` |
| AWS AccessKey | `(AKIA\|ASIA)[0-9A-Z]{16}` |
| Slack Token | `xox[baprs]-[0-9A-Za-z\-]{10,}` |
| 私钥 | `0x[a-fA-F0-9]{64}`（ETH 私钥长度） |
| Bearer/JWT | `eyJ...` 双段结构 |
| 密钥赋值 | `(api_key/token/secret/password/私钥/密钥/密码/令牌/访问凭证/授权码)\s*[:=是为]?\s*[A-Za-z0-9_\-]{10,}` |

注意：**讨论"怎么配 key"和"真的贴了 key"是两回事**——例如用户回复"把密钥给 agent 才手动解决"是在讲工作方法，不是泄露。命中后看等号右边有没有真实随机串。

## 3. 敏感/违规话题

| 类别 | 关键词（子集） | 定级参考 |

| 色情招嫖 | 约炮、招嫖、援交、裸聊、黄播、福利姬… | 中–高（看是招嫖还是粗口） |
| 毒品 | 冰毒、大麻、海洛因、贩毒、罂粟… | 高 |

翻墙类特殊说明：每逢假期 X 中文区会流传"刑期"传闻帖（"国庆翻墙三年起步"式），真伪无法证实；检测价值不在帖本身，而在提醒**用户本人的使用窗口风险**，报告里要把这条单独提到最高优先级。

## 4. severity 字段（扩展标记配色用）

`rules/sensitive-rules.json` 每条规则带 `severity`（high/medium/low），由扩展映射为描边配色；Python 报告定级与之一致但保留人工判断空间：

- **high**：politics、sensitive-figure、censorship-bypass、terror-violence、extreme-speech、hate-discrimination
- **medium**：全部凭据类、gambling、prostitution、drugs、self-harm-vulgar、自定义词
- **low**：全部 PII 类、scam-engagement

改 severity 只改 JSON，不改代码；`test_scan.py` 与 `extension/test/test_scanner.mjs` 的冻结预期只断言类别命中，不断言 severity，配色调整不破坏回归。

## 5. 定级口径（报告用）

- **高风险**：涉用户本人安全的（执法传闻类）、暴力煽动、歧视煽动、违法交易。
- **中风险**：色情低俗、争议言论、刷粉/虚假互动机器人网络。
- **低风险**：玩笑语境、粗口、误报排除项。
- **干净**：该面零有效命中。

刷粉模板帖识别特征：英文模板 "If you need Nk followers, Say RISE/YES, I will boost your page"、同文案多账号集中出现、无实质内容。它们本身不直接害用户，但用户若在评论区接龙会被判虚假互动协同，轻则限流。

## 5. 扩充规则的方法

1. 在 `TOPIC_RULES`/`PII_RULES`/`CRED_RULES` 里加 `(类别-名称, 编译后的正则)`；
2. 在本文档表格补一行；
3. 跑一遍历史数据回归，确认不炸误报率；
4. 正则尽量用负向先行断言排除数字粘连（`(?<!\d)`）。

## 6. 双通道校准（规则体检方法）

规则上线/修改后，按 `docs/validation-report-2026-10-01.md` 的方法做一轮交叉验证：

1. **通道 A（固定规则）**：`risk_scan.py` 或扩展 scanner 跑真实抓取数据；
2. **通道 B（AI 研判）**：LLM 对同一批数据逐条判定敏感/类别；
3. 对照 TP/FP/FN：FP 驱动语境收紧（裸词→结构/组合），FN 驱动模式扩充（注意多语言、拼写变体、emoji、跨行）；
4. **X 推文锚点间常跨行**：所有"两锚点组合"模式必须用 `[\s\S]{0,n}`，不能用 `[^\n]` 或 `.{0,n}`——这是实测翻车两次的教训；
5. 修正后把 FP/FN 案例与护栏案例写进 `scripts/fixtures/`，双端回归必须 PASS；
6. 政治态度类、通用引流 CTA 等无法用显式词覆盖的，登记为设计边界（见校验报告 §5），引导到 AI 通道或用户自定义词。
7. **用户复审是最终口径**：账号所有者逐条审查命中清单，裁定非敏感的条目一律转护栏并收紧规则（第一轮 6 条，见校验报告 §8）。区分「索取/供给/提问」「字面/辱骂」「社交 CTA/虚假服务」「显式词/纯 emoji」。
